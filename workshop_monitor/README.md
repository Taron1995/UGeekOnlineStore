# Workshop monitor: показатели смены по видео

Этап 1: первичные показатели по сотруднику, рабочему месту и смене.

| Показатель | Как определяется |
|---|---|
| Время у станка | человек (RF-DETR + ByteTrack) в полигоне `station_zone` (PolygonZone) |
| Время работы / простоя станка | движение в `machine_roi` (OpenCV), людей из маски исключаем; простой считается только в смену, без перерывов |
| Обработано заготовок | класс `workpiece` пересекает `piece_line` (LineZone) |
| Отсутствие вне перерывов | в смену никого в `station_zone` ≥ 30 с; интервалы режутся по перерывам 09:40–10:00, 13:00–14:00, 15:40–16:00 |
| Телефон | класс `phone` внутри рамки человека ≥ 3 с, клип сохраняется |
| Собрания ≥2 человек | двое ближе 1,5 роста ≥ 60 с, кроме одного станка и `gathering_zones`; запись на каждого участника |
| Сидит без движения | MediaPipe Pose: колено на уровне бедра и малое смещение скелета ≥ 120 с |

События пишутся в таблицу `events` (PostgreSQL), сводка по смене лежит во view `v_shift_metrics`: её читают API и Superset.

## Запуск в PyCharm
1. Откройте папку `workshop_monitor`, создайте venv (Python 3.11), `pip install -r requirements.txt`.
2. Поднимите БД: `docker compose up -d db` (нужен `.env`, см. `.env.example`).
3. `python -m monitor.run init-db`, затем `python scripts/seed_demo.py` (демо-график).
4. Заполните `config/config.yaml`: источники, полигоны, `detector.classes`.
5. `python -m monitor.run worker` — анализ; `API_KEY=... python -m monitor.run api` — отчёт на http://localhost:8000 (пароль = `API_KEY`).
6. Тесты: `pytest`.

Всё в контуре: `docker compose up -d` (db, worker, api, superset). Для GPU добавьте nvidia runtime сервису `worker` и `onnxruntime-gpu`; для Intel — `onnxruntime-openvino` и провайдер `OpenVINOExecutionProvider`.

## Модель
Предобученный RF-DETR знает человека и телефон (COCO: person=1, cell phone=77), но не ваши заготовки. Порядок:
1. CVAT: разметка кадров (SAM 2 подключается в CVAT как автоматическая разметка).
2. Экспорт «COCO 1.0» -> `training/split_coco.py` -> `training/train.py`.
3. `training/export_onnx.py` для ONNX Runtime/OpenVINO. Сверьте выходы ONNX и PyTorch на одном кадре (формат выходов и id классов я проверить не мог).
4. Пропишите `weights`/`onnx_path` и `classes` в конфиге.

## Клипы и лицензии
Клипы режутся FFmpeg с `-c copy` (без перекодирования), поэтому подходит LGPL-сборка; `Dockerfile` проверяет, что в сборке нет `--enable-gpl`. Автоматически клипы режутся только из видеофайлов. Для RTSP запишите поток в сегменты (`ffmpeg -i rtsp://... -c copy -f segment -segment_time 60 -strftime 1 ...`) и доработайте поиск сегмента по времени.

## Границы и важные оговорки
- **Личность.** Распознавания лиц нет. Сотрудник определяется по графику: кто в эту смену закреплён за рабочим местом (`POST /api/assignments`). Треки вне рабочей зоны привязываются к месту, где человек провёл ≥ 10 с. Если вы подменили сотрудника на месте, график нужно обновить.
- **Метрики оценочные.** Это сигналы для проверки человеком, а не доказательство нарушения. Поэтому есть клипы и поле `meta`. «Сидит без движения» может быть наладкой, чтением чертежа или ожиданием станка; в `meta` ничего лишнего нет, смотрите клип.
- **Проверено** тестами: расписание и перерывы, антидребезг, эвристика позы, и сквозной прогон на синтетических кадрах (присутствие, отсутствие, телефон, станок, простой, привязка к сотруднику). **Не проверено**: реальные RF-DETR, MediaPipe, ONNX, Docker, Superset, RTSP, собрания, заготовки и «сидит» на живом видео. Пороги в `thresholds` подбираются на ваших записях.
- **Данные о людях.** Видеонаблюдение за сотрудниками требует локального акта, ознакомления под подпись и защиты данных (152-ФЗ или местный аналог). API закрыт паролем, держите доступ к отчётам узким и задайте срок хранения клипов.
